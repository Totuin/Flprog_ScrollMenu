# Flprog_ScrollMenu — справочник разработчика

**Версия библиотеки:** 0.1.0  
**Дата проверки:** 18.11.2026  
**Заголовочный файл:** `flprogScrollMenu.h`  
**Язык:** C++11 и новее, Arduino-совместимое окружение.

Документ описывает фактическую реализацию 0.1.0, а не планируемые расширения. Библиотека реализована целиком в заголовочном файле. Изменений исходного кода для использования данного документа не требуется.

## 1. Назначение

`Flprog_ScrollMenu` формирует видимое окно большого списка и вычисляет позицию выделения. Применение: меню контроллера, выбор рецептов, списки параметров, журнал событий, многостолбцовые таблицы на дисплее.

Библиотека не управляет энкодером, кнопками или экраном. Она получает выбранный исходный индекс и фактическое количество записей, а затем копирует нужные элементы из исходных массивов в выходные массивы. Все колонки используют одно окно и одну позицию выделения.

```text
                        Count / Index / Refresh
                                  |
                                  v
    Исходные массивы ---> FlprogScrollMenu ---> Выходные массивы
     N записей                |                 R строк
      String                  |                  String
      int16_t                 |                  int16_t
      int16_t                 |                  int16_t
                              v
                    SelectedRow, VisibleCount,
                         FirstIndex, Index
                                  |
                                  v
                              Дисплей
```

- N — физическая ёмкость исходного массива.
- Count — число реально заполненных записей (может быть меньше N).
- R — фиксированное число строк окна.
- Index — выбранный индекс в исходном массиве.
- SelectedRow — выделенная позиция в выходных массивах.

Все индексы в API отсчитываются от нуля. Номер для пользователя при необходимости отображается как индекс + 1.

Библиотека не зависит от `Flprog_ArrayExchange`, EEPROM или драйверов дисплея. Функции чтения могут обращаться к RAM, кэшу EEPROM или вычислять значения. Функции записи обычно заполняют небольшие массивы RAM для отображения.

## 3. Архитектура классов

```text
FlprogAbstractScrollMenuColumn
  └── FlprogScrollMenuTypedColumn<T>
        ├── FlprogScrollMenuBoolColumn
        ├── FlprogScrollMenuInt8Column
        ├── FlprogScrollMenuUInt8Column
        ├── FlprogScrollMenuInt16Column
        ├── FlprogScrollMenuUInt16Column
        ├── FlprogScrollMenuInt32Column
        ├── FlprogScrollMenuUInt32Column
        ├── FlprogScrollMenuInt64Column
        ├── FlprogScrollMenuUInt64Column
        ├── FlprogScrollMenuFloatColumn
        ├── FlprogScrollMenuDoubleColumn
        └── FlprogScrollMenuStringColumn

FlprogScrollMenu
  └── хранит внешний массив указателей FlprogAbstractScrollMenuColumn*
```

Имена конкретных типов — псевдонимы (`using`), а не отдельные реализации классов. Менеджер ScrollMenu не зависит от типа данных колонки. Объекты колонок и массив их указателей принадлежат вызывающему коду, должны существовать в течение всей работы менеджера. Глобальное или статическое размещение хорошо соответствует кодогенерации FLProg.

Исходные и выходные массивы не должны перекрываться: заполнение окна выполняется по строкам, без промежуточного снимка всего источника.

## 4. FlprogAbstractScrollMenuColumn

Абстрактный базовый класс, задающий общий интерфейс любой колонки.

```cpp
FlprogAbstractScrollMenuColumn(uint16_t sourceSize, uint16_t outputSize);
virtual ~FlprogAbstractScrollMenuColumn();
uint16_t getSourceSize() const;
uint16_t getOutputSize() const;
virtual bool isReady() const = 0;
virtual void copyRow(uint16_t sourceIndex, uint16_t outputIndex) = 0;
virtual void clearRow(uint16_t outputIndex) = 0;
```

| Метод | Семантика |
|---|---|
| Конструктор | Фиксирует физические размеры источника и приёмника. |
| `getSourceSize()` | Возвращает ёмкость источника. |
| `getOutputSize()` | Возвращает ёмкость приёмника. |
| `isReady()` | Производный класс сообщает готовность к работе. |
| `copyRow()` | Переносит один элемент источника в указанную выходную строку. |
| `clearRow()` | Заполняет пустую выходную строку. |
| Деструктор | Виртуальный; не освобождает пользовательские массивы. |

Менеджер использует эти методы полиморфно. При создании собственного адаптера необходимо реализовать три чисто виртуальных метода и соблюдать фактические размеры массивов. Обычному пользовательскому блоку достаточно готовых типизированных колонок.

## 5. FlprogScrollMenuTypedColumn<T>

Типизированный адаптер. Для одной колонки тип исходного и выходного значений совпадает.

### 5.1. Функции обратного вызова

```cpp
using ReadFunction = T (*)(uint16_t index);
using WriteFunction = void (*)(T value, uint16_t index);
```

Чтение возвращает значение по исходному индексу. Запись принимает **сначала значение, затем индекс**. Это тот же порядок аргументов, что и у функций массивов FLProg, используемых в ArrayExchange.

Для `String` параметр записи передаётся по значению, а не по `const String&`. Сигнатура функции должна точно соответствовать типу колонки. Для экземпляра с `int16_t` нельзя передать функцию, возвращающую `int32_t`, без отдельного адаптера.

### 5.2. Конструктор

```cpp
FlprogScrollMenuTypedColumn(uint16_t sourceSize,
                           uint16_t outputSize,
                           ReadFunction read = nullptr,
                           WriteFunction write = nullptr);
```

`sourceSize` — физическая ёмкость исходного массива; `outputSize` — физическая ёмкость выходного. Приёмник должен иметь не меньше строк, чем окно меню. Колбэки можно передать сразу или назначить в `setup()`.

```cpp
FlprogScrollMenuInt16Column col(50, 5);
// Или:
FlprogScrollMenuInt16Column col2(50, 5, readValue, writeValue);
```

### 5.3. Методы

| Сигнатура | Назначение |
|---|---|
| `void setReadFunction(ReadFunction read)` | Назначает или заменяет функцию чтения. `nullptr` делает колонку неготовой. |
| `void setWriteFunction(WriteFunction write)` | Назначает или заменяет функцию записи. `nullptr` делает колонку неготовой. |
| `void setEmptyValue(T value)` | Значение для строк, не соответствующих реальным записям. |
| `bool isReady() const` | `true`, если оба указателя функций ненулевые. |
| `void copyRow(uint16_t sourceIndex, uint16_t outputIndex)` | Если обе функции назначены и индексы допустимы, вызывает запись результата чтения. |
| `void clearRow(uint16_t outputIndex)` | Если назначена функция записи и индекс допустим, записывает пустое значение. |
| `uint16_t getSourceSize() const` | Унаследованный размер источника. |
| `uint16_t getOutputSize() const` | Унаследованный размер приёмника. |

`setEmptyValue()` не переписывает массив немедленно. После изменения значения или замены ненулевых колбэков в действующей конфигурации нужно вызвать `menu.refresh()`, чтобы следующий `pool()` применил изменение. По умолчанию пустое значение равно `T()`.

### 5.4. Готовые типы

| Тип значения | Имя колонки | Пустое значение |
|---|---|---|
| `bool` | `FlprogScrollMenuBoolColumn` | `false` |
| `int8_t` | `FlprogScrollMenuInt8Column` | 0 |
| `uint8_t` | `FlprogScrollMenuUInt8Column` | 0 |
| `int16_t` | `FlprogScrollMenuInt16Column` | 0 |
| `uint16_t` | `FlprogScrollMenuUInt16Column` | 0 |
| `int32_t` | `FlprogScrollMenuInt32Column` | 0 |
| `uint32_t` | `FlprogScrollMenuUInt32Column` | 0 |
| `int64_t` | `FlprogScrollMenuInt64Column` | 0 |
| `uint64_t` | `FlprogScrollMenuUInt64Column` | 0 |
| `float` | `FlprogScrollMenuFloatColumn` | 0.0 |
| `double` | `FlprogScrollMenuDoubleColumn` | 0.0 |
| `String` | `FlprogScrollMenuStringColumn` | пустая строка |

Размер и точность `double` зависят от ядра контроллера. Другие типы допускаются посредством `FlprogScrollMenuTypedColumn<T>`, если тип пригоден для конструирования по умолчанию, копирования/присваивания и передачи в указанные функции. Библиотека не сериализует и не преобразует значения между типами.

## 6. FlprogScrollMenu — полный API

### 6.1. Создание и настройка

```cpp
explicit FlprogScrollMenu(uint16_t visibleRows);
bool setColumns(FlprogAbstractScrollMenuColumn* const* columns,
                uint16_t count);
```

`visibleRows` фиксируется при создании; ноль недопустим. `setColumns()` регистрирует внешнюю таблицу указателей, не копируя её. `count` здесь — количество колонок, а не записей.

`setColumns()` возвращает `false`, если число строк равно нулю, указатель на реестр отсутствует, количество колонок равно нулю, присутствует нулевой или повторный указатель либо хотя бы один приёмник меньше окна. При любом вызове старый реестр сбрасывается; неудачная регистрация оставляет меню без реестра. Успешная регистрация не означает, что callbacks уже назначены: это проверит `pool()`.

### 6.2. Входные параметры и обслуживание

```cpp
void setCount(int32_t count);
void setIndex(int32_t index);
void refresh();
void setAutoRefresh(bool enable);
bool pool();
```

| Метод | Назначение |
|---|---|
| `setCount(count)` | Задаёт фактическое количество занятых записей. Отрицательные значения при обработке становятся 0, слишком большие ограничиваются минимальной ёмкостью источников. |
| `setIndex(index)` | Задаёт запрошенный исходный индекс. При обработке ограничивается допустимым диапазоном. |
| `refresh()` | Устанавливает признак необходимости копирования на следующем `pool()`. Не копирует немедленно. Несколько вызовов до одного `pool()` объединяются. |
| `setAutoRefresh(enable)` | При `true` каждый успешный `pool()` заполняет окно заново. По умолчанию `false`. |
| `pool()` | Проверяет конфигурацию, рассчитывает эффективный индекс, окно и выделение, при необходимости вызывает колбэки. |

`pool()` возвращает `true` только если выполнен цикл заполнения выходных строк. Возвращаемое `false` не обязательно ошибка: выделение могло переместиться без изменения содержимого окна. Для различения ошибки используется `isReady()`.

Колбэки записи имеют тип `void`: возвращаемое `true` не подтверждает фактический успех пользовательской записи, только выполнение процедуры заполнения. Исключения, ошибки выделения памяти и ошибки пользовательских функций библиотека отдельно не обрабатывает.

### 6.3. Выходные параметры

| Сигнатура | Назначение |
|---|---|
| `bool isReady() const` | Меню прошло проверку конфигурации в `pool()`. Список при этом вполне может быть пустым. |
| `uint16_t getVisibleRows() const` | Физический размер окна, заданный конструктором. |
| `uint16_t getCount() const` | Эффективное количество записей. |
| `uint16_t getFirstIndex() const` | Исходный индекс первой строки окна; 0 при пустом списке. |
| `uint16_t getVisibleCount() const` | Количество заполненных строк, от 0 до `getVisibleRows()`. |
| `int32_t getIndex() const` | Эффективный исходный индекс, либо -1 при отсутствии выбора. |
| `int32_t getSelectedRow() const` | Индекс выделения внутри окна, либо -1 при отсутствии выбора. |
| `bool isRowValid(uint16_t row) const` | `true`, если конфигурация готова и строка соответствует существующей записи. |

Все результаты, кроме постоянного `getVisibleRows()`, отражают состояние после обработки `pool()` или сброса конфигурации. Простые сеттеры `setCount()` и `setIndex()` не обновляют выходы немедленно.

До первого успешного `pool()` готовность равна `false`, количество и начало окна равны 0, выбранные индексы равны -1, все строки считаются недействительными.

## 7. Алгоритм прокрутки

Обозначения: C — эффективное количество записей, R — размер окна, I — эффективный исходный индекс, F — начало окна, V — количество заполненных строк, S — выделенная строка.

1. Определить минимальную физическую ёмкость всех источников.
2. Ограничить C диапазоном от 0 до этой ёмкости.
3. Если C=0, I=-1. Иначе ограничить I диапазоном 0…C−1.
4. Сохранить прежнее F, но ограничить верхнюю границу значением `max(C - R, 0)`.
5. Если I меньше F, установить F=I. Если I больше или равен F+R, установить F=I−R+1. При пустом списке F=0.
6. Вычислить V=`min(R, C - F)`, S=`I - F` при наличии выбора, иначе -1.
7. При необходимости заполнить каждую строку каждой колонки. Для строки r < V прочитать источник F+r, записать в приёмник r. Остальные строки заполнить пустыми значениями.

Пример последовательных вызовов при восьми записях и пяти строках:

| Запрошенный I | F | Исходные индексы в окне | S |
|---:|---:|---|---:|
| 0 | 0 | 0, 1, 2, 3, 4 | 0 |
| 1 | 0 | 0, 1, 2, 3, 4 | 1 |
| 4 | 0 | 0, 1, 2, 3, 4 | 4 |
| 5 | 1 | 1, 2, 3, 4, 5 | 4 |
| 6 | 2 | 2, 3, 4, 5, 6 | 4 |
| 7 | 3 | 3, 4, 5, 6, 7 | 4 |
| 6 | 3 | 3, 4, 5, 6, 7 | 3 |
| 3 | 3 | 3, 4, 5, 6, 7 | 0 |
| 2 | 2 | 2, 3, 4, 5, 6 | 0 |
| 0 | 0 | 0, 1, 2, 3, 4 | 0 |

Окно не центрируется относительно выбора: оно сдвигается минимально, только когда выбор выходит за видимую границу. Поэтому при одинаковом I начало окна может зависеть от направления предыдущего движения. Циклический переход с конца в начало не реализован; его может организовать внешний обработчик индекса.

### 7.1. Граничные случаи

| Условие | Результат |
|---|---|
| C=0 | F=0, V=0, I=S=-1; при заполнении очищается всё окно. |
| 0 < C < R | F=0, V=C, хвост очищается, S находится в 0…C−1. |
| C≥R | V=R; окно не выходит за конец источника. |
| Запрошенный индекс отрицательный, C>0 | I=0. |
| Запрошенный индекс ≥ C, C>0 | I=C−1. |
| Один источник короче остальных | C ограничивается его ёмкостью. |
| Выходной массив больше R | Позиции после R−1 не изменяются. |
| Выходной массив меньше R | Конфигурация отклоняется. |
| Отсутствует колбэк | `pool()` возвращает false, `isReady()` — false, старые физические данные выходов не стираются. |

Запрошенное значение индекса хранится отдельно от эффективного. Если количество уменьшилось, а потом выросло, прежний запрошенный индекс может снова стать доступным, если внешний код не передал новый индекс. Для окончательного выбора синхронизируйте внешнее состояние с `getIndex()` и проверяйте наличие записей.

## 8. Когда обновляются выходные массивы

В обычном режиме `pool()` проверяет все колонки и рассчитывает окно, но переписывает выходные массивы только при одном из условий:

- первый успешный вызов после создания или сброса конфигурации;
- установлен признак `refresh()`;
- включён `setAutoRefresh(true)`;
- изменилось начало окна F;
- изменилось число заполненных видимых строк V.

**Важное уточнение:** изменение общего количества C само по себе не гарантирует повторного копирования, если F и V остались прежними. Изменение выделения внутри окна также не вызывает копирования. Библиотека не отслеживает изменение исходных значений автоматически.

Если записей восемь и строк пять, а указатель меняется с 0 на 1, данные остаются прежними; меняется только `getSelectedRow()`. Если редактируется название источника при неизменном окне, необходимо вызвать `refresh()`.

### 8.1. Импульсное обновление при входе на экран

Рекомендуемая схема пользовательского блока. `refreshSignal` — сигнал от логики переключения экранов, а не встроенная переменная библиотеки.

```cpp
static bool oldRefreshSignal = false;

menu.setCount(recipeCount);
menu.setIndex(recipeIndex);

if (refreshSignal && !oldRefreshSignal) {
    menu.refresh();
}
oldRefreshSignal = refreshSignal;

menu.pool();
selectedRow = menu.getSelectedRow();
```

При постоянном высоком уровне обновление происходит один раз. Следующий импульс требует предыдущего низкого уровня, обработанного блоком. Такой вход удобно добавить в пользовательский блок FLProg либо вызывать `refresh()` непосредственно при переключении экрана.

### 8.2. Изменения через UART

Пока ArrayExchange 0.1.2 не предоставляет отдельного импульса изменения данных. В дальнейшем предполагается добавить флаг успешной записи, который пользовательский блок сможет объединить с сигналом входа на экран. Это будущая доработка, не API текущей версии. Не следует вызывать вымышленный метод `isDataChanged()` в текущем коде.

`setAutoRefresh(true)` предусмотрен для задач, где непрерывное обновление действительно необходимо. Для списка рецептов предпочтительнее импульсное обновление; режим по умолчанию оставляем выключенным.

## 9. Интеграция с FLProg

### 9.1. Глобальные объявления

Пример соответствует реально проверенной схеме: три исходных массива по 50 записей, три выходных массива по 5 строк. Имена функций ниже условные; FLProg подставляет имена конкретных функций массива.

```cpp
#include <flprogScrollMenu.h>

FlprogScrollMenu menu(5);
FlprogScrollMenuStringColumn nameColumn(50, 5);
FlprogScrollMenuInt16Column temperatureColumn(50, 5);
FlprogScrollMenuInt16Column timeColumn(50, 5);

FlprogAbstractScrollMenuColumn* columns[] = {
    &nameColumn, &temperatureColumn, &timeColumn
};
```

### 9.2. Настройка в setup()

```cpp
nameColumn.setReadFunction(readRecipeNames);
nameColumn.setWriteFunction(writeVisibleNames);
temperatureColumn.setReadFunction(readRecipeTemperatures);
temperatureColumn.setWriteFunction(writeVisibleTemperatures);
timeColumn.setReadFunction(readRecipeTimes);
timeColumn.setWriteFunction(writeVisibleTimes);

bool configured = menu.setColumns(columns, 3);
// configured == false: не использовать выходы как действительные.
```

Предполагаемые функции должны иметь следующие сигнатуры (кодогенератор FLProg создаёт реализации):

```cpp
String readRecipeNames(uint16_t index);
int16_t readRecipeTemperatures(uint16_t index);
int16_t readRecipeTimes(uint16_t index);
void writeVisibleNames(String value, uint16_t index);
void writeVisibleTemperatures(int16_t value, uint16_t index);
void writeVisibleTimes(int16_t value, uint16_t index);
```

Для пустых строк можно задать специальное значение, например `nameColumn.setEmptyValue("")`. Для чисел предпочтительнее скрывать виджет по действительности строки, а не распознавать пустые строки по нулю: ноль может быть допустимым значением данных.

### 9.3. Основной цикл

```cpp
menu.setCount(recipeCount);
menu.setIndex(recipeIndex);
menu.pool();

int32_t selectedRow = menu.getSelectedRow();
uint16_t visibleCount = menu.getVisibleCount();
```

В текущем испытанном проекте count берётся из нулевого элемента EEPROM-массива параметров (`readFlprogArray_194641594(0)`), index — из `_gtv3`, результат `getSelectedRow()` поступает на выход пользовательского блока. Три выходных массива в RAM имеют по пять элементов. На экране пять строк значений и пять иконок, которые выделяются по индексу строки 0…4. Временный экран проверен аппаратно.

### 9.4. Рекомендуемые параметры и порты будущего блока

Это предложение для кодогенерации, а не новый API.

| Элемент блока | Тип | Связь с библиотекой |
|---|---|---|
| Число видимых строк | Параметр `uint16_t` | Конструктор меню |
| Колонки, типы, источник и приёмник | Настройки блока | Конструкторы адаптеров и `setColumns()` |
| Count | Вход `int32_t` | `setCount()` |
| Index | Вход `int32_t` | `setIndex()` |
| Refresh | Импульсный вход `bool` | `refresh()` по фронту |
| SelectedRow | Выход `int32_t` | `getSelectedRow()` |
| FirstIndex | Дополнительный выход `uint16_t` | `getFirstIndex()` |
| VisibleCount | Дополнительный выход `uint16_t` | `getVisibleCount()` |
| EffectiveIndex | Дополнительный выход `int32_t` | `getIndex()` |
| Ready | Дополнительный выход `bool` | `isReady()` |
| Copied | Дополнительный выход `bool` | Возвращаемое значение `pool()` |

Для пяти строк допустим знаковый `int8_t` или `int16_t` выход SelectedRow, но универсальный блок должен учитывать полный диапазон API (до 65534 и значение -1). Для отдельной иконки выделения условие `Ready && SelectedRow == row`. Для скрытия пустых строк — `Ready && row < VisibleCount` либо `isRowValid(row)`.

### 9.5. Выбор рецепта и использование данных

Меню формирует отображение, но не подтверждает рецепт для технологического процесса. При выборе проверять `isReady()`, наличие записей и эффективный индекс. Для получения исходного индекса действительной строки использовать `getFirstIndex() + row`; не читать источники по -1. Параметры процесса нужно отдельно проверять на допустимость и фиксировать при подтверждении выбора, не использовать изменяемые выходные массивы меню как рабочие уставки.

При расширении источников с 50 до 100 элементов необходимо изменить физические размеры соответствующих массивов и конструкторов колонок; размер окна 5 остаётся прежним. Саму библиотеку менять не нужно. Если исходные массивы одновременно подключены к ArrayExchange, их размеры там также должны соответствовать новой ёмкости.

## 10. Производительность, память и ограничения

- `pool()` синхронный и неблокирующий в смысле отсутствия собственных ожиданий, таймеров или задержек. Время выполнения зависит от пользовательских колбэков.
- При отсутствии копирования сложность O(K), где K — число колонок; при заполнении O(R×K). Регистрация с проверкой повторных указателей — O(K²).
- Для пяти строк, трёх колонок и полностью заполненного окна один цикл заполнения вызывает 15 чтений и 15 записей. При V заполненных строках — V×K чтений и R×K записей. Без копирования этих вызовов нет.
- Библиотека не выделяет память для исходных/выходных массивов, не создаёт снимок всей таблицы и не использует динамический контейнер для колонок. `String` и пользовательские типы могут выделять память самостоятельно.
- Размер экземпляров зависит от размера указателя, выравнивания, ABI и типа значения; для конкретной платформы измерять `sizeof(menu)` и `sizeof(column)`. Размеры массива указателей и объектов данных учитываются отдельно.
- Размеры окон, источников и количество колонок представлены `uint16_t` (до 65535). Практическое ограничение определяется RAM и доступным временем цикла.
- Не передавать указатели на локальные временные объекты или таблицу указателей, срок жизни которых закончится до работы меню.
- Библиотека не обеспечивает потокобезопасность; `pool()`, изменение конфигурации, `refresh()` и обращение к массивам должны выполняться в согласованном контексте основного цикла. Энкодер может работать в IRQ, но значение индекса следует безопасно передать в этот цикл. `volatile` сам по себе не обеспечивает атомарность составной операции.
- После изменения конфигурации или готовности колбэков проверять `isReady()`. Физическое старое содержимое невалидных выходных массивов может остаться в памяти.
- Библиотека предназначена для интерфейса. Она не проверяет безопасные технологические параметры, не гарантирует атомарность внешней загрузки рецептов и не заменяет независимые аппаратные защиты.
