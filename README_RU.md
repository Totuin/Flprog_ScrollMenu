# Flprog_ScrollMenu 0.1.0

Независимая от оборудования библиотека видимого окна списка. Общий контроллер прокрутки и произвольное количество типизированных колонок. Индексы с нуля. Не зависит от ArrayExchange, UART, EEPROM, дисплея или энкодера. Не владеет исходными и выходными массивами, не выделяет для них память. Тип `String` может выделять память своими средствами.

## Подключение в FLProg

Глобальные объявления (пример: 100 исходных записей и пять видимых строк):

```cpp
#include <flprogScrollMenu.h>
FlprogScrollMenu menu(5);
FlprogScrollMenuStringColumn nameColumn(100, 5);
FlprogScrollMenuInt16Column temperatureColumn(100, 5);
FlprogScrollMenuInt16Column timeColumn(100, 5);
FlprogAbstractScrollMenuColumn* columns[] = {
    &nameColumn, &temperatureColumn, &timeColumn
};
```

В `setup()` назначить фактические функции, сгенерированные FLProg:

```cpp
nameColumn.setReadFunction(readRecipeNames);
nameColumn.setWriteFunction(writeVisibleNames);
temperatureColumn.setReadFunction(readRecipeTemperatures);
temperatureColumn.setWriteFunction(writeVisibleTemperatures);
timeColumn.setReadFunction(readRecipeTimes);
timeColumn.setWriteFunction(writeVisibleTimes);
menu.setColumns(columns, 3);
```

Имена функций здесь условные. Сигнатуры совпадают с ArrayExchange: `T read(uint16_t index)` и `void write(T value, uint16_t index)`. Исходные и выходные массивы должны быть раздельными и действительно иметь указанные размеры. Выходные массивы рекомендуется размещать в обычной RAM, не EEPROM. Сам массив указателей и адаптеры должны существовать всё время работы меню.

В основном цикле или пользовательском блоке:

```cpp
menu.setCount(recipeCount); // реально занятые записи, не размер массива
menu.setIndex(recipeIndex); // выбранный индекс, начиная с 0
menu.pool();
int32_t selectedRow = menu.getSelectedRow();
```

`selectedRow == -1` означает отсутствие выделения. `getVisibleCount()` показывает количество заполненных строк. Для дисплея `menu.isRowValid(row)` позволяет скрыть пустые поля; `menu.getFirstIndex() + row` — исходный индекс действительной строки. Для показа номера человеку прибавить 1. Независимо от наличия выделения проверяйте `isReady()` и действительность строки перед использованием данных.

## API

### FlprogScrollMenu

| Метод | Назначение |
|---|---|
| `explicit FlprogScrollMenu(uint16_t visibleRows)` | Число видимых строк фиксируется при создании. Ноль — недопустимая конфигурация. |
| `bool setColumns(FlprogAbstractScrollMenuColumn* const* columns, uint16_t count)` | Подключает реестр колонок и сбрасывает окно. Возвращает false при пустом реестре, null, повторе указателя или недостаточном размере выхода. Не проверяет колбэки до pool. Неверный реестр отключает предшествующий. |
| `void setCount(int32_t count)` | Фактическое число элементов. В pool ограничивается диапазоном от 0 до минимальной ёмкости всех исходных массивов. |
| `void setIndex(int32_t index)` | Запрашиваемый исходный индекс. В pool ограничивается диапазоном 0..count-1; если count=0, эффективный индекс -1. |
| `bool pool()` | Проверяет конфигурацию, пересчитывает окно и выделение, при необходимости копирует колонки. true — выходные массивы переписаны; false — не переписаны (выделение могло измениться). |
| `void refresh()` | Принудительное заполнение при следующем pool(), даже если окно не сдвинулось. |
| `void setAutoRefresh(bool enable)` | Если true, каждый pool заново заполняет выходные массивы. По умолчанию false. |
| `bool isReady() const` | Результат последней проверки конфигурации в pool. |
| `uint16_t getVisibleRows() const` | Физическое число строк окна. |
| `uint16_t getCount() const` | Эффективное количество записей после pool. |
| `uint16_t getFirstIndex() const` | Исходный индекс первой видимой строки. При пустом списке 0. |
| `uint16_t getVisibleCount() const` | Количество действительно заполненных строк. |
| `int32_t getIndex() const` | Эффективный исходный индекс, -1 при пустом списке или неверной конфигурации. |
| `int32_t getSelectedRow() const` | Индекс выделения в выходных массивах, -1 при пустом списке или неверной конфигурации. |
| `bool isRowValid(uint16_t row) const` | Проверяет, является ли строка заполненной и конфигурация готовой. |

Методы setCount/setIndex задают запрос; getters, кроме getVisibleRows, возвращают состояние после последнего pool. Запрошенный индекс сохраняется до следующего setIndex; если после уменьшения списка он оказался за границей, getIndex вернёт допустимый индекс. Если нужно синхронизировать внешний индекс, присвойте ему getIndex после проверки наличия записей. При пустом списке не читайте исходный массив по индексу -1.

### FlprogScrollMenuTypedColumn<T>

`FlprogScrollMenuTypedColumn(uint16_t sourceSize, uint16_t outputSize, ReadFunction read = nullptr, WriteFunction write = nullptr)` — адаптер исходного и выходного массива одного типа. Можно назначить функции позднее в setup.

| Метод | Назначение |
|---|---|
| `void setReadFunction(T (*read)(uint16_t))` | Функция чтения исходного массива. |
| `void setWriteFunction(void (*write)(T, uint16_t))` | Функция записи выходного массива: сначала значение, потом индекс. |
| `void setEmptyValue(T value)` | Значение для неиспользуемых строк. По умолчанию T(): false, ноль или пустая String. После изменения вызвать refresh. |
| `bool isReady() const` | Обе функции назначены. |
| `uint16_t getSourceSize() const` | Ёмкость источника. |
| `uint16_t getOutputSize() const` | Ёмкость выхода. |
| `void copyRow(uint16_t sourceIndex, uint16_t outputIndex)` | Внутренний виртуальный метод копирования с проверкой индексов. |
| `void clearRow(uint16_t outputIndex)` | Внутренний виртуальный метод заполнения пустой строки. |

Готовые имена (псевдонимы шаблона): `FlprogScrollMenuBoolColumn`, `FlprogScrollMenuInt8Column`, `FlprogScrollMenuUInt8Column`, `FlprogScrollMenuInt16Column`, `FlprogScrollMenuUInt16Column`, `FlprogScrollMenuInt32Column`, `FlprogScrollMenuUInt32Column`, `FlprogScrollMenuInt64Column`, `FlprogScrollMenuUInt64Column`, `FlprogScrollMenuFloatColumn`, `FlprogScrollMenuDoubleColumn`, `FlprogScrollMenuStringColumn`. Другие типы можно подключать через шаблон при наличии соответствующих функций и конструктора по умолчанию.

## Алгоритм окна

Пять строк, 100 записей, движение вперёд:

| Входной индекс | Первая запись окна | Выделенная строка |
|---:|---:|---:|
| 0 | 0 | 0 |
| 1 | 0 | 1 |
| 4 | 0 | 4 |
| 5 | 1 | 4 |
| 6 | 2 | 4 |
| 99 | 95 | 4 |
| 98 (назад) | 95 | 3 |

Выделение перемещается внутри окна; при выходе за его границу окно сдвигается минимально. Циклического перехода нет, его при необходимости реализует внешний обработчик индекса. При уменьшении количества записей окно и индекс ограничиваются автоматически. Если записей меньше строк, хвост заполняется пустым значением. Если записей нет, все видимые строки очищаются. Выходы за пределы установленной ёмкости исключаются на уровне менеджера и адаптеров. Неиспользуемые позиции выходного массива сверх visibleRows библиотека не трогает.

## Обновление содержимого и планировщик

По умолчанию pool проверяет индекс и количество каждый вызов. Если изменилось только выделение внутри заполненного окна, копирования нет. Если внешняя программа поменяла данные исходных массивов, но не индекс и размер видимого участка, вызовите refresh() перед pool. Если отдельного сигнала изменения нет, вызывайте refresh периодически (например, в выделенной задаче экрана) либо включите setAutoRefresh(true) и вызывайте pool с нужной периодичностью. Назначение новых функций или пустого значения в уже работающей конфигурации также требует refresh.

Библиотека синхронная: pool копирует максимум visibleRows × число колонок, а не весь источник. Не вызывайте pool, setIndex, setCount или колбэки из обработчика прерывания. Энкодер передаёт индекс в основной цикл с подходящей для контроллера синхронизацией; изменение исходных массивов, pool и обновление экрана выполняются последовательно. При ошибке конфигурации isReady=false; старое содержимое выходов не считается действительным, физически не стирается. Колбэки записи не возвращают статус: успешный pool означает их вызов, а не независимую верификацию записи. Библиотека не обеспечивает согласованность технологических данных при конкурентных изменениях и не является защитой автоклава.
